# My Arcade visual review

Every capture listed here was generated by the opt-in `CAPTURE_PR=1` block in `tests/e2e/pr-captures.spec.ts` and
**opened and inspected image by image** before this document was written. CI uploads the same set into the
`pr-visual-captures` artifact with seven-day retention; the images are not committed to Git.

Browser: Chromium 149.0.7827.0, headless, `prefers-reduced-motion` default unless stated. Local values are invented
fixtures written by the test — no real visitor storage, and no screenshot of a storage inspector.

This is automated capture review only. **No physical-device and no assistive-technology testing is claimed.**

## Method note on zoom

Browser zoom is captured as the equivalent CSS-pixel viewport (a 1280×1024 screen divided by the zoom factor), not
with the CSS `zoom` property. Media queries ignore `zoom`, so `zoom: 4` would photograph a scaled desktop layout
instead of the reflow under review.

## Observations recorded but deliberately not changed

- **Reserved metric area.** Cards with no saved result show a small amount of whitespace between the message and the
  Play/Guide links. `min-height: 4.25rem` on the metric slot is intentional: it stops the links from jumping when the
  loading line is replaced by real metrics. The trade is deliberate and documented rather than removed.
- **Arcade "All arcade games" card wrapping.** At 1440 px the four-across catalogue grid wraps some titles one word
  per line. Comparing `my-arcade-entry-arcade.jpg` with the pre-existing
  [`pr-17-captures/desktop-arcade-recent-populated.jpg`](./pr-17-captures/desktop-arcade-recent-populated.jpg) shows
  the identical layout before this branch, so it is a pre-existing Arcade issue and out of scope for this focused
  pull request.
